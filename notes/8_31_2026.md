# 8/31/2026 — Track A RAG walkthrough

Phase 2 path: booklet → chunks → Qdrant → hybrid retrieve → LLM answer with citations.
API entry: `POST /api/v1/rag/query` (SSE). Service: `backend/services/rag.py`.

Gate: `rag_configured()` is simply “is `OPENAI_API_KEY` set?”. No key → no indexing / query returns 503.

---

## Pipeline (end-to-end)

```
loaders (strip pricing)
  → splitters (parent/child)
  → embeddings (OpenAI + Redis cache)
  → store (Qdrant upsert)
  → retriever (dense + BM25 → RRF → expand → rerank)
  → generate (cited answer, stream)
  → cache (exact + semantic answer cache)
```

RBAC: query only searches plans the caller can already see (`list_visible_plans`). Provider admins also get `organization_ids` filter so Qdrant never returns another insurer’s chunks.

---

## 1. `loaders.py` — ingest + pricing scrub

- PDF via `pypdf`, else UTF-8 text.
- `strip_pricing_content`: drops markdown sections whose heading looks like pricing/premiums/rate card, plus individual premium lines.
- Why: employers must not see competitor pricing; generation prompt also forbids prices. Scrubbing at ingest is defense-in-depth so embeddings never contain rate cards.

## 2. `splitters.py` — small-to-big (parent/child)

| | Parent | Child |
|---|---|---|
| size / overlap | 1500 / 150 | 400 / 80 |
| role | generation context (`parent_text`) | retrieval / citation quote (`text`) |

Flow:

1. Split markdown by `#` / `##` → section name in metadata.
2. Each section → parent chunks.
3. Each parent → child chunks, each carrying `parent_id`, `parent_text`, `section`, plan/org ids.

Retrieve on children (precise match); generate from parent text (more context). Citations still use the short child `text`.

## 3. `embeddings.py` — CachedOpenAIEmbeddings

- Redis key `emb:{model}:{sha256(text)}`, TTL 7 days.
- Batch: fill from cache, call OpenAI only for misses, write back.
- `embed_query` = single-item `embed_documents`.

## 4. `store.py` — Qdrant

- Collection cosine, dim from settings.
- Point id = UUID5 of `document_id:parent_id:chunk_index` (stable re-upsert).
- Payload = metadata + `text`.
- `dense_search`: filter by `plan_id` / `organization_id`, score threshold, optional vectors (needed for MMR).
- `scroll_all_payloads`: rebuilds in-memory BM25 after index runs.
- `delete_document_chunks` before re-index so stale points disappear.

## 5. `indexing.py` — lifecycle

- Seed known plan booklets under `data/plans/` → `PlanDocument` rows (`PENDING`).
- `index_pending_documents`: ensure collection → embed/upsert → `INDEXED` or `FAILED` → rebuild BM25.
- Uploads land under `data/uploads/{document_id}/`.

## 6. `retriever.py` — hybrid retrieve (focus area before rerank)

Order inside `retrieve()`:

1. **Dense** — embed query → Qdrant top `rag_dense_k` (with vectors).
2. **MMR** — diversify dense hits (`λ` relevance vs redundancy); needs `_vector` on records.
3. **Sparse** — in-process BM25 over all payloads; same plan/org filters.
4. **RRF** — `1/(60 + rank)` fused across dense+sparse; key = `document_id:parent_id:chunk_index`.
5. **`expand_parents`** — one hit per `parent_id` (dedupe siblings).
6. **`rerank`** — LLM (or fused order fallback) down to `rag_rerank_k`.

Mental model: dense ≈ meaning, BM25 ≈ exact policy terms (“waiting period”, “maternity”), RRF merges without score calibration, MMR reduces near-duplicates, parent expand is small-to-big, rerank is final relevance polish.

## 7. `rerank.py` — LLM listwise rerank (where you left off)

**When it no-ops:** `len(records) <= k` → return as-is (already short enough).

**Prompt:** system asks for JSON only `{"order": [int, ...]}` — indices of passages, best first. Human message = question + numbered passages (plan, section, first 500 chars of text) + “at most k”.

**Parse (`_parse_order`):**

1. Prefer first `{...}` JSON blob → `order` list of ints.
2. On parse failure → scrape all digits from the reply.
3. Keep only indices in `[0, size)`.

**Assemble:** walk LLM order, skip dupes, stop at `k`. If LLM returned fewer than `k`, pad from original fused order (indices not yet seen).

**Failure:** any exception → log warning, return `records[:k]` (trust RRF order). Retrieval still works without OpenAI chat for rerank if dense path already ran; full query still needs embeddings + chat for answer.

Design notes:

- Listwise (reorder whole set) vs pairwise (compare pairs) — cheaper for small candidate sets after fusion.
- Truncating passages to 500 chars keeps token cost down; parent_text is used later in generation, not here.
- Indices only (not rewriting text) avoids the model inventing clauses at rerank time.

## 8. `generate.py` — answer + citations

- System: answer only from numbered sources; cite with `[n]`; no premiums; no invented clauses; optional COMPARISON FACTS from rules engine may be stated without doc cite.
- Context uses `parent_text` (fallback `text`) — generation gets the bigger window.
- `citations_from_answer`: regex `[n]` → map to records → short child quote (≤280) for UI.
- `astream_answer` for SSE tokens.

## 9. `cache.py` + service cache path

| Cache | Key / structure | Purpose |
|---|---|---|
| Exact answer | `rag:exact:{org}:{role}:{plans}:{sha(q)}` | identical question |
| Semantic answer | list `rag:sem:...` of `{embedding, payload}`, cosine ≥ threshold | near-paraphrases |
| Embeddings | see embeddings.py | avoid re-embedding chunks/queries |

Lookups scoped by org + role + plan set so one tenant/role cannot hit another’s cached answers. TTL 12h for answers.

Service flow (`stream_rag_answer`): exact → semantic → retrieve → stream tokens → final event with citations → store both caches.

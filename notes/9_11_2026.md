### Auth Hardening (Access + Refresh Tokens)

- Planned and implemented replacing the single 24h JWT bearer token (stored in `localStorage`, no revocation) with:
	- Short-lived (15 min) JWT access tokens, unchanged shape.
	- Rotating, revocable refresh tokens (opaque, SHA-256-hashed server-side in a new `refresh_tokens` table; single-use with rotation; reuse of an already-rotated token revokes the rest of that user's active tokens).
	- Both delivered as httpOnly cookies (`access_token` path `/`, `refresh_token` path `/api/v1/auth`), `Secure` in production, `SameSite=Lax`.
- Backend changes: `backend/core/config.py` (new `access_token_expire_minutes`/`refresh_token_expire_days` settings), new `RefreshToken` model + Alembic migration `0006_refresh_tokens`, new token helpers in `backend/core/security.py` (`issue_refresh_token`, `rotate_refresh_token`, `revoke_refresh_token`), `backend/api/deps.py::get_security_context` now accepts either the `Authorization` header or the cookie, new `/auth/refresh` and `/auth/logout` endpoints, `/auth/register` also issues the refresh cookie.
- Frontend changes: `frontend/src/lib/api.ts` sends `credentials: "include"` everywhere, removed all `localStorage` token handling, added silent refresh-and-retry-once on 401, added `logout()`; `frontend/src/lib/auth.ts` dropped `getToken`/`setToken`/`isAuthenticated`; `AuthGuard`, `AppShell`, login/register pages, and the root redirect page updated accordingly.
- Fixed a dev-environment cookie gotcha: default API URL was `127.0.0.1:8102`, which browsers treat as a different site from `localhost:3100`, silently breaking `SameSite=Lax` cookies. Changed the `api.ts` fallback and `frontend/.env.local` to `localhost:8102`.
- Kept the `Authorization: Bearer` header path working intentionally so `scripts/smoke_pec_waiting.py` and Swagger UI are unaffected by the browser-side change.

### RAG Pipeline Hardening (SBC/health-plan production requirements)

Reviewed the existing RAG stack in detail before changing anything — hybrid retrieval
(dense Qdrant + BM25 + RRF + MMR) was already solid; the real gaps were table-blind
chunking, no page-number tracking, a listwise (not cross-encoder-style) reranker, no
metadata-first SSE event, and prompts without explicit anti-arithmetic discipline.

- Added `backend/rag/layout.py`: detects markdown pipe tables and whitespace-aligned
  (naive PDF-extraction) tables as atomic blocks so a table is never split mid-row.
- `backend/rag/loaders.py`: new `load_pages()` extracts PDFs page-by-page (1-indexed,
  layout-preserving mode) instead of joining all pages before chunking; pricing-strip
  logic refactored to carry skip-state across page boundaries correctly.
- `backend/rag/splitters.py`/`indexing.py`: chunking now runs per page, threading
  `page_number` through chunk metadata; table blocks bypass the recursive splitter
  entirely (kept as one chunk each, `kind="table"`).
- `backend/rag/rerank.py`: added `rerank_pairwise()` — true cross-encoder-pattern
  reranking (independent `score(query, passage)` per candidate, concurrent Ollama
  calls) replacing the old single listwise "give me an order" call as the default path
  in `retriever.py`. Kept on Ollama, no new ML dependency, per explicit decision.
- `backend/rag/generate.py`: new shared `RAG_STRICT_DISCIPLINE` prompt block (mandatory
  per-claim citation, verbatim-only numbers, explicit "never compute/derive a number"
  rule, exact refusal wording) prepended to both route prompts. New
  `sources_from_records()` helper for the metadata-first SSE event.
- `backend/services/rag.py` and `backend/agents/nodes.py`/`services/agent.py`: both SSE
  endpoints now emit a `{"type":"sources",...}` event carrying full chunk metadata
  (plan_id, section, document_id, page_number, score) **before** any token events,
  instead of only revealing sources in the terminal event.
- **Found and fixed a real pre-existing bug** while wiring the above: `services/agent.py`'s
  `graph.astream(...)` call was missing `subgraphs=True`. Since token/sources streaming
  happens inside the `policy`/`compare` LangGraph *subgraphs*, custom-stream events never
  reached the outer stream at all — meaning live token-by-token streaming for
  `/agents/chat` was silently broken before this session touched it; the UI just sat
  blank until the final answer landed. Fixed and verified live over HTTP.
- `backend/agents/nodes.py`: added a log-only (never mutates the answer) unattributed-
  number check in `verify_node`, alongside the existing pricing-leak guard.
- Frontend: `useAgentStream` hook (`frontend/src/lib/hooks/useAgentStream.ts`) splits the
  sources event from token accumulation and distinguishes a genuine network drop from a
  user cancel; `chat/page.tsx` refactored to use it and render source/page chips.
- Verified live end-to-end over real HTTP (not just unit tests): confirmed SSE order is
  exactly `sources → tokens → final` on both endpoints; for a plan whose policy actually
  excludes pre-existing conditions, the model correctly answered with the mandated exact
  refusal phrase instead of guessing — the strict prompt working as designed, not just in
  theory.
- Found unrelated, pre-existing dev-DB schema drift (`plan_versions` missing several
  columns from later migrations — `alembic_version` is stuck at `0001` while
  `AUTO_CREATE_TABLES=true` never alters existing tables) blocking `/agents/chat` for
  `employer_admin`/`platform_admin` specifically; not touched, flagged for separate
